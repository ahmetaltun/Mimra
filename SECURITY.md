# Security Policy

## Supported Versions

Mimra is currently maintained for the following versions on supported platforms:

| Version | Supported | Architecture | Target OS |
|---|---|---|---|
| `0.2.x` | :white_check_mark: | Apple Silicon (`arm64`) | macOS 15.0+ |
| `0.1.x` | :white_check_mark: | Apple Silicon (`arm64`) | macOS 15.0+ |
| `< 0.1.0` | :x: | Any | Unsupported |

## Reporting a Vulnerability Privately

Please **do not open public GitHub issues or discussions** containing security vulnerability details, exploits, or reproduction payloads.

To report a vulnerability privately, use **GitHub Private Vulnerability Reporting**:

- **Advisory Submission**: [Submit a Security Advisory](https://github.com/ahmetaltun/Mimra/security/advisories/new)

When submitting a report, please include:
1. A clear description of the vulnerability and potential impact.
2. The exact Mimra version, macOS version, and Apple Silicon hardware.
3. Minimal, reproducible proof-of-concept steps or synthetic pasteboard payloads.
4. Any relevant logs or stack traces (ensure logs do **not** contain personal or sensitive data).

We follow coordinated vulnerability disclosure and will acknowledge receipt, investigate the issue, and provide remediations through release updates.

## Security Boundaries & Scope

Mimra is designed with a strict security and privacy hierarchy:
`security/privacy > data correctness > reliable paste > keyboard accessibility > performance > feature completeness`.

### In Scope
- **Privacy Prefiltering**: Enforcement of concealed type markers (`org.nspasteboard.ConcealedType`, `org.nspasteboard.AutoGeneratedType`, `com.agilebits.onepassword`, and password manager bundle IDs).
- **Process & FFI Boundaries**: Swift-to-Rust memory safety, bounds checking in FTS5/regex engines, and non-blocking background C-ABI calls via UniFFI.
- **Local Storage Isolation**: SQLite database integrity, file permission scoping (`~/Library/Application Support/Mimra/`), and safe corruption recovery.
- **Update Verification**: Sparkle 2 update feed validation, Ed25519 signature checks, and TLS transport security.

### Out of Scope
- Attacks requiring physical access to an unlocked device or root (`sudo`) access.
- System integrity failures resulting from disabled System Integrity Protection (SIP).
- Vulnerabilities within macOS AppKit, Accessibility APIs, or the underlying OS kernel.
- Memory tampering or debugger injection by other processes running with matching user entitlements.

For detailed STRIDE threat analysis and boundary specifications, see [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md).
