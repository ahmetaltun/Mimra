# Mimra — AI & Engineering Agent Guidelines

> This document outlines non-negotiable rules and instructions for all engineering agents working on the Mimra codebase, derived from [MIMRA_MASTER_PLAN.md](MIMRA_MASTER_PLAN.md).

---

## 1. Core Operating Principles

1. **Security & Privacy First**:
   - `security/privacy > data correctness > reliable paste > keyboard accessibility > performance > feature completeness > visual decoration`.
   - Never log raw clipboard contents, preview snippets, OCR text, file paths, tokens, or URL query parameters.
   - Any secret marker (`org.nspasteboard.ConcealedType`, `org.nspasteboard.AutoGeneratedType`, `com.agilebits.onepassword`, etc.) or excluded application must be filtered out in Swift **before** reaching Rust, SQLite, or disk.

2. **Strict Component Boundaries**:
   - **SwiftUI / AppKit**: Controls UI, `NSPanel`, `NSStatusItem`, event interception, hotkeys, and Accessibility paste. Never writes raw SQL or directly accesses SQLite.
   - **Rust (`RustCore`)**: Owns the SQLite database, FTS5 index, deduplication, normalization, retention cleanup, and search ranking. Must never interact with AppKit/UIKit APIs.
   - **UniFFI Bridge**: Synchronous C-ABI layer. Must be called exclusively from off-main background workers or actors in Swift—**never block the main actor on Rust calls**.

3. **Incremental Development & Smallest Vertical Slices**:
   - Implement only one small, unblocked task at a time as tracked in [docs/STATUS.md](docs/STATUS.md).
   - Never generate entire architectural layers speculatively. Write unit/integration tests with every slice.
   - Do not perform unrelated refactoring.

4. **Zero Fabrication**:
   - Never claim an unverified or incomplete feature is shipped.
   - If a test cannot be executed directly on macOS hardware, mark it explicitly as `NOT VERIFIED` and document the exact terminal commands required to run it.

5. **Explanatory Error Handling**:
   - Always return typed, descriptive error messages explaining what went wrong and how to remediate it.
   - No silent failures, catch-all unhandled drops, or panics across the FFI boundary.

## 2. Definition of Done (DoD) for Every Task

Before marking a task as completed:
- [ ] Task satisfies its linked `F-` feature ID and acceptance criteria in [MIMRA_MASTER_PLAN.md](MIMRA_MASTER_PLAN.md).
- [ ] Rust passes `cargo fmt --check`, `cargo clippy -- -D warnings`, and `cargo test --locked`.
- [ ] Swift code builds cleanly under Swift 6 strict concurrency (`-strict-concurrency=complete`).
- [ ] Negative and edge-case tests are written (empty content, multi-representation, invalid Unicode, large buffers).
- [ ] No raw clipboard payloads appear in logs, test output, or debug artifacts.
- [ ] Updates made to [docs/STATUS.md](docs/STATUS.md) and [docs/DECISIONS.md](docs/DECISIONS.md).
- [ ] Run `graphify update .` in the project root if the Graphify CLI tool is available.

## 3. Reporting Format for Completed Tasks

When completing a task, summarize using this structured format:

```markdown
## Task Completed
`P#-##` — Concise task title

## Scope of Changes
- Modified files and modules
- Linked Feature (`F-###`) and Test (`T-###`) IDs

## Implementation Notes
- Core architectural decisions and modular structure
- Error handling and boundary safeguards

## Verification & Test Results
- Environment: OS version, chip architecture, Rust/Xcode toolchains
- Automated test commands and outcomes
- Manual checks executed (or marked NOT VERIFIED with commands)

## Privacy & Security Verification
- Sensitive markers filtered? [Yes/Not Applicable]
- Logs clean of clipboard content? [Yes]

## Next Steps
- Next unblocked task from [docs/STATUS.md](docs/STATUS.md)
```
