## 1. Architectural Boundaries & Asset Classification

Mimra operates under the fundamental principle:  
`security/privacy > data correctness > reliable paste > keyboard accessibility > performance > feature completeness > visual decoration`.

### 1.1 Assets Under Protection
1. **User Clipboard Payloads:** Text, rich text, images, and file paths containing potentially confidential business, personal, or financial information.
2. **Authentication Credentials & Tokens:** Passwords, passkeys, OTPs, API keys, and session tokens generated by or copied from password managers.
3. **Local Database & Indices:** SQLite database file (`mimra.sqlite`), write-ahead log (`mimra.sqlite-wal`), and FTS5 full-text search index.
4. **Keystroke & Input Injection Surface:** Synthetic `Command-V` event posting mechanism.

### 1.2 Boundary Architecture
```
┌─────────────────────────────────────────────────────────────┐
│                       macOS Pasteboard                      │
│      NSPasteboard.general (System WindowServer / IPC)       │
└──────────────────────────────┬──────────────────────────────┘
                               │ Metadata Inspection (Types & BundleID)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│              Swift Layer: PrivacyFilter.swift               │
│  [Pre-Filter Gate] - Fail-closed check BEFORE payload read  │
│  • Mandatory concealed markers (1Password, Bitwarden, etc.) │
│  • Custom user ignored UTIs                                 │
│  • Excluded applications by bundle ID or filesystem path     │
│  • Universal Clipboard filter (remote clipboard toggle)     │
│  • User capture pause and 'ignore next copy' states         │
└──────────────────────────────┬──────────────────────────────┘
                               │ Allowed Payloads Only
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 RustCore Storage & FTS Engine               │
│  • In-memory BLAKE3 deduplication hashing                   │
│  • Local SQLite database (0700 permissions)                 │
│  • Multi-dimensional retention eviction (count, age, size)  │
│  • Zero network dependencies, zero background daemons       │
└─────────────────────────────────────────────────────────────┘
```

## 2. Threat Analysis & Mitigations

### Threat 1: Leakage of Credentials from Password Managers
* **Threat:** The user copies a master password, credit card number, or TOTP code from a password manager (e.g. 1Password, Bitwarden, KeePassXC, Apple Keychain, Strongbox, Dashlane). If captured, this sensitive secret enters persistent history, FTS5 indices, and previews.
* **Mitigation:**
  1. `PrivacyFilter` examines `NSPasteboardItem.types` **before extracting any payload bytes**.
  2. If any concealed or transient marker (`org.nspasteboard.ConcealedType`, `org.nspasteboard.AutoGeneratedType`, `org.nspasteboard.TransientType`, `com.agilebits.onepassword`, etc.) is detected on any item in the pasteboard, the entire pasteboard change event is rejected immediately with `.drop(.concealedMarker)`.
  3. Zero bytes are extracted into memory.
  4. The event never reaches Rust, SQLite, FTS5, Vision OCR, image cache, or OS logs.
* **Verification:** `tests/privacy_filter_tests.swift` (`T-PRIV-01`).

### Threat 2: Secret Exfiltration via Network Telemetry
* **Threat:** Clipboard data or usage analytics could be transmitted to remote servers via network libraries, crash reporters, or third-party SDKs.
* **Mitigation:**
  1. **Zero Network Dependencies:** Neither `Cargo.toml` in `RustCore` nor the Swift Xcode project imports `URLSession`, `Network.framework`, `reqwest`, `hyper`, `curl`, or socket libraries.
  2. Mimra has no telemetry, no analytics SDKs, no cloud sync, and no auto-updater network callers in v1.
  3. Binary audit verifies zero network framework links.
* **Verification:** Static binary review and offline network inspection.

### Threat 3: Clipboard Feedback Loops & Spurious Duplicates
* **Threat:** When Mimra auto-pastes an item, writing to `NSPasteboard` increments `changeCount`, causing `ClipboardMonitor` to detect its own write as a fresh user copy.
* **Mitigation:**
  1. `PasteCoordinator` marks every outgoing item with `ClipboardProvenance.provenanceType` (`com.mimra.provenance`) and source bundle ID `com.mimra.app`.
  2. `PasteCoordinator` records `lastSelfWrittenChangeCount` in `ClipboardProvenance`.
  3. `ClipboardMonitor` drops any event matching `lastSelfWrittenChangeCount` or possessing `com.mimra.provenance`.
* **Verification:** `tests/provenance_tests.swift` (`T-CAP-05`).

### Threat 4: Unauthorized Keystroke Injection & Input Hijacking
* **Threat:** Synthetic `Command-V` posting could inadvertently inject clipboard data into a password field, screen lock, or unintended background process.
* **Mitigation:**
  1. **Secure Event Input Check:** Before posting keystrokes, `PasteCoordinator` checks `IsSecureEventInputEnabled()`. If active, keystroke injection is aborted, falling back cleanly to `copiedOnly(reason: .secureInputActive)`.
  2. **Password Field Inspection:** Uses Accessibility API (`AXUIElementCopyAttributeValue`) to check if the focused element has role or subrole `AXSecureTextField`. If true, keystrokes are aborted, falling back to `copiedOnly(reason: .passwordFieldFocused)`.
  3. **PID Validation:** Re-queries frontmost application immediately before posting to ensure the user did not switch apps or spaces during the activation window.
* **Verification:** `tests/paste_regression_lab_tests.swift` (`T-PASTE-04`).

### Threat 5: Data Resurrection via Asynchronous OCR or Thumbnails
* **Threat:** An image is copied, triggering a background Vision OCR analysis. If the user deletes or clears the item before OCR finishes, a stale callback might update the database and resurrect the deleted item.
* **Mitigation:**
  1. `OCRService` tracks active `Task` handles by item ID. When an item is deleted or history cleared, pending OCR tasks are immediately cancelled.
  2. Rust `update_item_ocr_text` runs within a transaction that verifies the item still exists in `history_items` before touching `search_fts`. If the item was deleted, the update is discarded safely.
  3. Image preview and thumbnail caches evict entries immediately upon item deletion.
* **Verification:** `tests/ocr_race_protection_tests.swift` (`T-SRCH-04`, `T-PREV-02`).

### Threat 6: Sensitive Payload Exposure in OS Logs & Diagnostics
* **Threat:** Unredacted log statements could output clipboard strings, URLs, file paths, or OCR text to Apple Unified Logging (`os_log`) or Console.app.
* **Mitigation:**
  1. All Swift log statements use `privacy: .public` strictly on non-sensitive structural metadata (e.g. UUIDs, item counts, durations, PIDs, error enum codes).
  2. Raw text payloads, previews, OCR strings, and file paths are never logged.
  3. RustCore production code contains no `println!` or logging macros.
* **Verification:** Static audit and log stream verification.
